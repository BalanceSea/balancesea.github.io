# AI 添加插件文档规范

将本文件与插件源码、构建文件和实际生成的配置文件一起提供给 AI。AI 必须先完成事实核对，再创建文档。

## 必须读取的来源

AI 必须检查以下内容；缺少任何来源时应明确列出缺口，不得猜测：

1. `plugin.yml` 或 `paper-plugin.yml`
2. Maven/Gradle 构建文件与依赖声明
3. `src/main/resources/` 中的所有文件
4. 所有配置加载、默认值、校验、迁移和保存代码
5. 所有命令注册、别名、参数与权限检查代码
6. 所有 PlaceholderAPI 变量、事件监听器、数据库表与软依赖钩子
7. 插件首次运行后实际生成的完整目录

## 配置文档硬性要求

AI 必须：

- 列出插件生成或读取的每一个配置文件，包括语言、GUI、数据、菜单、存储和功能配置。
- 为每一个叶子配置路径建立独立表格行，不能把一个配置段合并成一项。
- 记录配置文件、完整路径、数据类型、默认值、允许值或范围、单位、是否必填、生效方式和详细行为。
- 说明配置修改后是即时生效、执行重载命令生效，还是必须重启服务器。
- 标记密码、Token、数据库连接串等敏感项，并使用安全占位值，禁止写入真实凭据。
- 完整展示每一个默认配置文件，保持键顺序、注释和层级，不使用省略号。
- 核对“配置项参考表”与“完整配置文件”，保证双方条目一一对应。
- 记录旧版本配置迁移、废弃键、自动补全行为和无效值的回退策略。
- 动态映射配置如 `titles.<id>.*` 必须列出该映射下允许的全部子项。
- 如果源码与默认文件不一致，必须指出差异及运行时实际采用的值。

AI 禁止：

- 只展示常用配置或示例片段。
- 使用“其他配置类似”“以此类推”或省略号跳过内容。
- 根据插件名称臆造命令、权限、配置或兼容版本。
- 将软依赖描述成强制依赖。
- 在无法读取源码时声称配置清单完整。

## 页面内容要求

每个插件页面必须包含：

1. 插件概览、目标用户和真实使用场景
2. 所有主要功能及边界
3. 精确安装环境、Java/Minecraft/服务端版本
4. 强制依赖和软依赖，说明缺失时的行为
5. 全部命令、别名、参数、权限和默认授权对象
6. 全部占位符、返回值和示例
7. 全部配置文件与全部配置项
8. 数据库、跨服、性能、重载和升级注意事项
9. 作者固定为 `MoutainSeaL`
10. 作者 QQ 固定为 `3643203568`

## 目录与路由

新插件必须使用以下 Vue 模块结构：

```text
src/plugins/<小写插件名>/
└── index.js
```

完成后运行：

```bash
npm run build
```

`src/plugins/registry.js` 会通过 `import.meta.glob` 自动发现所有插件。构建脚本为每个插件生成目录入口，页面链接使用 `/plugins/<插件名>/` 形式，不显示 `.html`。
